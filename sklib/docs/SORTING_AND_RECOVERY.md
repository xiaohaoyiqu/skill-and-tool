# 库内分拣与失败处理

当前提供资料类型识别、个人标签和使用状态，以及无需关键词的分拣浏览。分类记录存入本地状态库，导出到记录仓库；来源文件保持原位置。已支持跨页选择并批量修改标签、状态、收藏；按用途自动打标签与物理移动文件未实现。

## 分拣入口

界面清空关键词即可浏览，按来源、资料范围、程序类型、标签、收藏和状态筛选，按名称、最近收录/更新或来源路径排序。关键词存在时按检索相关性排序，仍可限制到选定队列。

| 队列 | 具体含义 | 处理方式 |
|---|---|---|
| 全部条目 all | 当前范围内全部位置记录 | 逐条查看正文和来源，设置标签及状态 |
| 未分类 unclassified | 没有个人标签的条目 | 添加用途、技术栈等标签；收藏本身不代表已分类 |
| 待复核 needs_review | 状态仍为 unreviewed | 了解后改为 to_try / useful / not_recommended |
| 有警告 warnings | 索引中的元数据警告，例如缺字段、格式异常 | 详情显示警告原因；修正来源并重扫。仅修改个人状态不会消除来源警告 |
| 重复技能 duplicates | 内容哈希相同、位置不同的技能 | 各位置分别查看和标注；不自动删除或合并来源文件 |

队列可以重叠：没有标签且未复核的条目会同时计入两队列。计数依据当前来源/类型/标签/状态筛选，不受当前队列限制；浏览 total 是选定队列的准确位置条目数。重复判断会参考库内其他来源，当前筛选可能只展示其中一部分位置。搜索中的副本折叠继续保留，分拣浏览始终逐位置列出，避免整理到另一份副本的笔记。

标签首尾空格会去除、重复值会合并，纯空白标签被拒绝。标签大小写保留。未分类按个人标签判断，不把来源元数据中的标签自动当成人工整理结果。

CLI 返回 JSON：

```powershell
python -m sklib browse --queue unclassified --kind all
python -m sklib browse --queue needs_review --sort recent --limit 25
python -m sklib browse --queue duplicates --root E:\materials
python -m sklib browse --project-type python --tag 科研
python -m sklib search "PDF" --queue unclassified --json
python -m sklib annotate <id> --tag 文档处理 --tag PDF --state to_try
```

MCP 新增只读 `list_library`，参数包括 queue、kind、root、project_type、tags、favorite、state、sort、limit、offset、max_chars。可从无关键词的队列浏览进入 `get_skill` 和 `read_skill_file`。MCP 不提供修改标签或移动文件的工具。

MCP get_skill 默认正文预算 24000 字符，按 next 继续至完成；续页带上 next 的两种版本参数，正文或换行变化时从头读取。工具响应超出 1 MiB 会返回 tool_result_too_large，减少 limit/max_chars；如果元数据本身过大，可用 read_skill_file 读取正文。界面草稿已支持当前浏览器内刷新与新页面恢复；草稿和正式保存分别标记，见 [批量与草稿恢复](BATCH_AND_DRAFTS.md)。

界面扫描已改为后台任务。排队、运行、取消、部分完成、失败和服务重启后的未确认结果分别保留，见 [后台任务状态与恢复](SETUP_AND_TASKS.md)。取消不会强制中断磁盘/Git 调用；来源在排队后被移除或重扫时，旧任务拒绝写回。CLI 和原同步 HTTP 接口行为保持独立。

浏览每页最多 100 项，offset 最多 100000，默认字符预算 24000。返回 next_offset 时继续；字符预算使一页不足 limit 时也不会跳过条目。计数为数据库快照，不探测每个源文件的实时存在状态。源文件改变后需重新扫描。

## 失败结果的统一字段

CLI 的运行错误在 stderr 返回 JSON；HTTP 返回对应的 400/403/404/503 与 JSON；MCP 的预期工具执行失败返回 isError=true、文本与 structuredContent。JSON-RPC 格式/方法/参数错误仍采用协议错误码。示例：

```json
{
  "error": "database is locked",
  "code": "database_busy",
  "operation": "annotate",
  "retryable": true,
  "outcome": "unchanged",
  "recovery": "等待当前数据库写入完成后重试；不要删除状态库。"
}
```

retryable 只表示原因消除后可以重试，不会自动重新执行业务请求。outcome=unchanged 表示本次受管数据操作未提交；partial 表示已有成功批次或正常条目提交；unknown 表示不能据通信或 Git 错误判断最终结果；completed 用于操作已经完成、仅通知或活动记录失败的警告。

CLI 退出码：0 完成，2 运行错误或参数错误，3 扫描部分完成，130 用户取消。部分扫描的完整报告仍输出到 stdout；不能只看是否有 JSON 或是否收录了一些条目。

## 按功能处理失败

| 功能与失败情形 | 已保留的内容 / 当前状态 | 后续处理 |
|---|---|---|
| 分类、标签、队列参数非法 | 不修改记录 | 修正参数；纯空白标签不会变成“已分类” |
| 浏览 / 搜索无结果 | 正常空结果；不是失败 | 检查必含词、清除筛选、切换队列，确认来源是否已登记和重扫。空结果不能证明磁盘上不存在资料 |
| 浏览 / 搜索遇到数据库锁或读取失败 | 原有记录不改；界面保留上次结果并标明失败，禁用旧分页 | 原因消除后重新检索。等待期间旧结果暂时不可点击，避免选错条目 |
| 来源路径错误、文件总数超限、根目录重叠、并发来源冲突 | 本轮不写索引条目 | 修正目录或预算，等待另一操作完成，再扫描；source_conflict 可重试 |
| 单文件编码、访问权限、大小错误或目录深度超限 | 正常条目可提交；失败条目的旧索引保留；本轮不清理未见条目 | complete=false，退出码 3；按 failures 中的 path/code/recovery 修正后重扫 |
| YAML / 项目元数据不合法或缺解析依赖 | 正文仍可收录，附元数据警告 | 在有警告队列检查；修正格式/依赖后重扫，不把警告当作完整识别成功 |
| 单条索引写入过程出现可隔离错误 | SAVEPOINT 回滚该条目的正文和全文索引，避免两者不同步 | 查看失败明细；其他正常条目继续处理 |
| 扫描发生 SQLite 写入 / 提交失败 | 外层事务回滚本轮数据库变化 | 检查锁、磁盘与数据库状态后重扫；不自动删除数据库 |
| 扫描取消或提交后的进度通知失败 | 提交前取消回滚本轮；提交后通知失败仍返回成功并附 progress_warning | 先用 status 确认。进度通知失败无需因此重复扫描 |
| 移除索引来源失败 | 同一事务内回滚；来源文件不参与修改 | 原因修正后重试；移除成功后重复移除返回 0 条，也是正常结果 |
| 已移除来源的笔记暂时无条目 | 注释仍保留，快照的 orphaned_annotations 保留其内容 | 同路径重新收录会恢复关联；可从旧快照映射新来源，或为孤立 ID 指定目标。缺少原定位时不按名称盲猜 |
| 全文读取时条目已移除、文件丢失、路径变为链接 | 拒绝读取，个人记录保留 | 检查来源，恢复文件或重扫后重新选择 ID |
| 指定正文版本已变 | source_changed，未返回所要求的旧版本 | 重扫、重新选择当前版本；未指定版本时会读取当前文件并标 stale |
| 资源为二进制、超大、非法路径、权限或编码错误 | 不修改文件，不执行脚本 | 按文件类型使用外部程序；文本编码可显式覆盖。越界路径不会通过重试放行 |
| 资源续页读取失败 | 已成功片段保留；临时失败可再次点击继续读取 | 版本不变可重试同一页；resource_changed 会清空拼接内容，需从第 1 行重读 |
| 标签 / 笔记 / 收藏 / 状态保存失败 | 注释、FTS 和活动记录在同一事务回滚；界面保留当前输入 | 修正原因后手动重试。当前页面保留输入不等于浏览器关闭后仍有草稿 |
| 写请求已发出但连接中断 / 响应无法解析 | 结果标为尚未确认，可能已提交；不自动重发 | 先保留当前输入，再重新读取记录确认。浏览器测试覆盖“服务已保存但响应丢失” |
| status / history 查询失败 | 不删除或修复数据 | 检查状态目录、锁和磁盘；数据库格式不支持时使用匹配版本，保留原库备份 |
| 语义查询服务未启动、模型不存在或返回非法响应 | 词法索引、笔记、已有向量保留；不悄悄切换检索模式 | 检查已安装的本地向量模型 / 端点；可显式切换 lexical，不自动下载模型 |
| 向量建库中途失败 / 取消 | 已完成批次保留，当前失败批次回滚；错误带 embedded/processed 等进度 | 修正后重跑，默认跳过匹配的成功向量；force 过程失败时暂用词法，并重新执行 --force |
| 向量维度不符或缓存损坏 | embedding_incompatible / embedding_corrupt；词法与注释保留 | 用 embed --force --model <模型名> 重建。不会因损坏自动清空其他记录 |
| Git 未初始化、正在其他 Git 操作中、记录锁超时 | 不代替用户完成 merge/rebase，不删除锁文件 | 初始化记录仓库、等待当前操作或人工处理未完成操作，再检查状态并预览 |
| 快照导出失败 | 原 catalog.json 通过临时文件与 replace 保留；未替换前失败不覆盖原内容 | 检查磁盘、权限与文件占用后重新导出 |
| 预览后记录或 Git HEAD 已变 | preview_stale，拒绝提交，也不覆盖已预览文件 | 重新预览并核对，不复用旧 token |
| Git 提交因身份、钩子、锁等失败 | catalog.json 可能已经暂存，其他暂存内容保持原状 | 先 records status / records log，修正原因，再预览提交；不自动 reset 或重试 |
| Git 命令超时，或提交成功后读不到 HEAD | git_outcome_unknown | 先查历史和仓库状态，确认是否已提交；不要根据报错盲目再提交 |
| Git 已成功，本地活动日志写入失败 | committed=true，返回提交号与 activity_log_failed 警告 | 保留提交号；不重做提交。records status / log 不依赖索引数据库，可用于确认 |
| Git 记录内容无变化 | committed=false，正常结果 | 不生成空提交 |
| 评测文件非法、嵌套过深、相关项类型错误或过大 | 在查询前校验整个数据集，拒绝不合法输入 | 修正 JSON；最多 1000 个案例、单文件 2 MiB。评测查询失败不会修改资料 |
| 来源检测遇到权限、链接、根目录缺失、数量/深度上限 | 检查不改索引；complete=false、state=attention，不把未见条目认定为删除 | 修正原因后重新检测；需要发现同大小同时间戳的修改时使用 sources check --verify |
| 自动刷新任务失败、部分完成或接受状态未知 | 原后台任务结果保留；同一磁盘变化不反复入队，最近任务号保留到后续检测供界面确认 | 查任务和来源报告；修正产生新变化，或手动刷新。关闭检测不取消已入队任务 |
| 整理快照写出失败或超过 16 MiB | 替换前失败保留旧备份；不删除资料以缩小快照 | 检查磁盘和输出路径；用 --root、--annotated-only 或 --offset/--limit 分批导出 |
| 导入文件、映射、类型、重复 ID 或目标冲突非法 | 写入前校验；不执行快照内容，不注册来源 | 修正文件或显式指定目标；多个同内容目标不任意挑选，未匹配整理内容可保留为孤立注释 |
| 导入/迁移预览后目标或有效计划已变 | restore_preview_stale，全部未写入 | 保留快照、映射和处理选择，重新预览；分页共享同一令牌 |
| 导入/迁移写入中途失败 | 注释、FTS 和活动事件统一回滚 | 排除锁、磁盘或数据原因后重新预览并应用 |
| 导入响应丢失或无法解析 | 结果未知；界面保留文件/映射，不自动重发，并禁用旧应用令牌 | 重新预览确认当前值；已经导入的记录会显示相同 |
| MCP 参数 / 帧错误或数据库执行失败 | 坏帧不破坏下一条请求；预期执行失败是可解释的工具错误 | 修正请求后继续；服务进程退出则由宿主重新启动。活动工具取消协议未实现 |
| HTTP 非本地来源、旧会话令牌、非法请求体 | 403/400，拒绝写入 | 使用当前 loopback 地址和会话，先保留草稿再刷新；不降低访问检查 |
| 浏览器取消请求，响应头/正文发送时断连或超时 | 结束连接，不向已断开的连接重复发错误响应；业务操作不会因此重发 | 查询可手动重试；若是写请求丢失响应，仍须先重新读取确认是否已保存 |
| 本地界面端口占用、启动依赖缺失 | 服务未成功启动 | 更换 --port；按 pyproject.toml 在所选环境准备依赖，不自动全局安装 |

检查 Git 最终状态可以用界面的“检查仓库状态”与“查看提交历史”，或：

```powershell
python -m sklib records status
python -m sklib records log
python -m sklib records preview
```

失败明细最多保留前 200 项，同时给出完整 failure_count 和 errors_truncated。界面来源卡片展示前 3 项原因与处理提示。致命失败发生在扫描登记前或整个事务回滚时，不会写入一份“成功的来源报告”；应保留本次 CLI / HTTP 错误。界面后台任务另行保留失败与中断结果，没有自动调度重试器。

## 验证与实际限制

`tests/test_sorting_recovery.py` 使用故障注入与临时真实 Git 仓库验证事务、批次恢复、导出替换、提交结果和跨接口错误。浏览器验证 503 保存失败、保存成功但响应丢失、不自动重发、输入保留、队列刷新和检索失败保留旧结果。

这些检查覆盖关键失败路径，没有穷举所有操作系统错误、磁盘硬件故障和断电情形。批量标签、浏览器草稿、预览快照导入和跨路径注释迁移已实现；不自动修复损坏数据库或自动应用备份。已有来源与笔记需要诊断时，先关闭应用并保留状态目录和记录仓库，不以删除数据库作为默认修复步骤。浏览器草稿另行导出保留，完整用法见 [SOURCES_AND_RESTORE.md](SOURCES_AND_RESTORE.md)。

事务和单条回滚设计对照 [SQLite transactions](https://www.sqlite.org/lang_transaction.html) 与 [savepoints](https://www.sqlite.org/lang_savepoint.html)，MCP 执行失败结果对照 [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。
