# 批量分拣与浏览器草稿

本轮实现批量标签、状态、收藏，以及刷新和新页面后的草稿恢复。分类记录写入资料库，草稿保存在浏览器；两者的保存状态分别显示。

## 批量分拣

在检索结果左侧勾选位置，或点击“选择本页”。可以跨页选择，最多 100 项；改变关键词或筛选条件会清空选择。展开“核对已选位置”查看名称、路径、当前标签、状态和收藏，也可逐项移出。

设置操作后，点击“应用到已选条目”：

| 操作 | 行为 |
|---|---|
| 添加标签 | 保留旧标签，去除首尾空白并合并重复值 |
| 移除指定标签 | 只移除指定的标签，大小写敏感 |
| 替换全部标签 | 将所选位置的标签替换为输入值；空输入需明确改选“清空标签” |
| 清空标签 | 清空所选位置的标签 |
| 状态 / 收藏 | 默认不修改，可与标签操作同时设置 |

个人笔记保留。搜索折叠结果只处理显示的那个位置，其他副本不随之修改；无关键词浏览则逐位置列出。源文件和目录保持原位置。

整批使用一个 SQLite 事务，先验证全部条目和合并后的标签上限，再写入注释、全文索引和活动记录。任何条目失效、发生版本冲突或写入失败，整批回滚。没有实际变化的条目跳过写入；全批无变化时不新增活动记录。

选择时记录 annotation_revision。其他页面、CLI 或批量操作改变记录后，旧选择会返回 annotation_conflict。选择和操作设置保留；点击“重新读取选中记录”获取当前状态，展开核对后再提交。程序不会自动采用新版本重试写入。

## 草稿保存与恢复

编辑标签、笔记、状态或收藏后，界面将完整表单写入当前浏览器的 localStorage，并显示“草稿已保存在此浏览器，尚未保存到资料库”。点击“保存记录”后才写入资料库，供其他界面和 Agent 检索。

- 刷新页面或关闭当前页后重新打开，在同一浏览器、相同本机地址和相同资料库下，能够恢复草稿。
- 每个页面发布独立的草稿副本；同一页面继续输入时只替换自己上一份副本，不覆盖另一页的输入。
- 与当前已保存版本相符的草稿可自动恢复；来自较早版本的副本留在草稿箱，手动打开后显示当前保存内容供核对。
- 保存返回成功，或重新读取确认草稿内容已经保存时，清理对应副本。输入在保存请求期间继续变化，后续输入保留为新草稿。
- 来源移出索引后，草稿仍可在草稿箱查看、复制或导出；同一路径重新收录后可恢复。移动来源到新路径不自动迁移草稿。

“草稿箱”可查看各副本、恢复、删除单份或导出 JSON。导出包含内存中尚未成功持久化的草稿，并保留无法解析的浏览器记录供恢复。删除当前打开的副本会恢复该条目已读取的保存内容。

浏览器存储不可用或空间不足时，输入留在本页并显示失败状态，不伪装为持久化成功。可以保存正式记录或导出草稿后再关闭页面。无法解析的旧草稿保留原记录，不自动清空。

草稿按资料库的绝对状态目录隔离，仍受浏览器 origin 限制：127.0.0.1 与 localhost、不同端口、不同浏览器或用户配置文件各自独立。使用程序打印的固定地址可保持一致。清除网站数据、无痕会话结束或浏览器清理策略可能删除浏览器草稿。资料库备份和 Git catalog 不包含草稿，需要时使用“导出草稿”。

## 同时编辑的冲突处理

个人记录的 annotation_revision 由位置、内容和更新时间计算，区别于技能原文的 revision。界面提交单条笔记或批量修改都会带上所读取的记录版本；在同一写事务内检查版本，避免静默覆盖新内容。

冲突时保留输入，并显示当前已保存的标签、状态、收藏和笔记。核对或合并表单后，可点击“保留输入，基于显示的版本继续编辑”，再保存。这个按钮只更新本地草稿的基础版本，不立即修改资料库；再次发生变更仍会拒绝旧版本。

详情加载期间禁用旧条目的输入，资料库位置未确认前也禁用笔记编辑。加载中点击的详情标签在新内容返回后继续保留，避免快速切换后笔记页被正文覆盖。运行期间检测到资料库位置改变，要求先保留草稿并刷新页面。

## 失败后如何处理

| 情况 | 保留的内容 | 后续操作 |
|---|---|---|
| 批量中有失效条目或版本冲突 | 整批未修改；选择与设置保留 | 移除失效项，或重新读取并核对后提交 |
| 批量第 2 项写入 / 全文索引失败 | 注释、全文索引和活动记录整批回滚 | 修正数据库或文件占用原因后重试 |
| 批量响应丢失 | 结果可能已提交，选择和设置保留 | 先重新读取选中记录确认；不会自动重发 |
| 单条保存版本过期 | 较新的正式记录和本地输入均保留 | 核对当前记录，再明确采用其版本继续编辑 |
| 单条保存成功但响应丢失 | 草稿仍保留 | 重新读取可确认已保存内容并清理相符副本 |
| 草稿写入浏览器失败 | 最新输入留在内存，旧的持久化副本保留 | 保存正式记录或导出后再关闭页面 |
| 草稿解析或删除失败 | 原浏览器记录保留 | 导出后检查；正式保存结果不因此报错 |
| 原来源被移除 | 草稿副本留在浏览器 | 从草稿箱查看或导出，恢复来源后再打开 |

## CLI 与 API

```powershell
.\.venv\Scripts\sklib.exe batch-annotate <id1> <id2> --preview
.\.venv\Scripts\sklib.exe batch-annotate <id1> <id2> --tag 前端 --state to_try
.\.venv\Scripts\sklib.exe batch-annotate <id1> <id2> --tag-mode remove --tag 旧标签
.\.venv\Scripts\sklib.exe batch-annotate <id1> <id2> --tag-mode clear --no-favorite
.\.venv\Scripts\sklib.exe batch-annotate <id1> <id2> --tag 前端 --expected-versions versions.json
```

这些命令沿用 --home / SKLIB_HOME 设置；跨目录使用时显式传相同的绝对 --home。--preview 只返回当前位置和注释摘要。versions.json 是所选每个 ID 到 annotation_revision 的完整映射，单条 annotate 也可传 --expected-revision。为保持旧调用兼容，CLI/Python/API 未提供预期版本时表示对当时记录执行操作；需要并发保护的调用方应显式传版本。界面始终传版本。

GET /api/annotations?ids=... 提供最多 100 项注释摘要；POST /api/annotate-batch 原子应用修改，字段为 ids、tags、tag_mode、state、favorite、expected_revisions。既有 POST /api/annotate 增加 expected_annotation_revision。写请求继续校验本机会话；MCP 仍保持四个只读工具。

## 性能与验证

注释修改使用 FTS5 普通内容表的 UPDATE，仅改变 annotation 列，应用层不重新生成名称、描述和正文的分词文本。FTS5 内部仍可能重建索引行，不据此承诺只写入少量磁盘数据。缺失全文索引行时回退到完整重建。依据见 [SQLite FTS5 普通表更新说明](https://www.sqlite.org/fts5.html)。

同一个临时索引中，用 50 条每条约 10350 字符的合成正文、交替顺序、预热后各测 5 次：完整刷新中位 131.39 ms，只更新注释字段中位 47.93 ms，全文索引完整性检查通过。原始数据见 [batch-performance.json](batch-performance.json)。这是本机短样本，不外推为所有数据集的速度保证。

新增 12 项非浏览器回归覆盖批量模式、非法参数、整批回滚、标签上限、无变化行为、并发版本检查、检索版本一致、FTS 更新与修复、HTTP/CLI 和草稿副本/存储失败。8 项 Edge 流程覆盖持久化恢复、双页冲突、草稿导出、批量失败、响应丢失和原有流程。跨版本和打包结果见 [验证记录](VALIDATION.md)。
