## 第四轮：库内分拣与逐功能失败处理

新增 `browse`、HTTP `/api/browse` 和 MCP `list_library`；无关键词时界面直接浏览五个队列。相同技能按位置分别列出，标签/状态可将当前记录移出未分类与待复核队列。字符预算、分页、空标签、重复标签、跨筛选的队列计数已验证。

回归文件为 `tests/test_sorting_recovery.py`，共 18 项。初始故障复现确认：部分扫描返回成功退出码、单条写入失败留下正文/FTS 不一致、向量失败缺少已完成进度、评测相关项对象触发 TypeError、Git 提交完成却因活动记录失败而报错、MCP 数据库错误未成为可解释工具错误。现均修复。

- 单条索引 SAVEPOINT 与外层事务分别验证可隔离失败和数据库失败回滚；注释失败保留旧笔记。
- 205 个坏文件的报告保留前 200 项，并报告完整数量；部分扫描 CLI 返回 3。
- 向量第 2 批失败时保留第 1 批，重跑跳过成功向量；同一批写入失败全部回滚；force 可修复损坏向量。
- 导出 replace 失败保留旧 catalog；真实 Git 身份失败后保留暂存目录，修正身份、重新预览后成功提交。
- Git 提交成功但 SQLite 活动记录失败时返回 committed=true 与警告；索引数据库不可用时 records status 仍可检查 Git HEAD。
- MCP 和 HTTP 返回统一失败字段，HTTP 实际保存事务失败验证 outcome=unchanged；随后请求继续可用。
- 提交后的进度通知失败保留成功结果；不会把已完成索引误报为失败。

真实浏览器增加故障流程：503 保存失败保留输入与旧笔记；模拟保存成功后响应丢失，提示结果尚未确认，输入保留且只发出一次写请求；重新浏览后队列计数更新；检索失败显示上次结果并禁用旧分页。浏览器检查还发现并修复新增来源筛选导致 390 像素布局溢出、检索等待期间可点击旧结果的竞态；修复后三项流程均通过。

逐功能失败后保留什么、如何确认状态和重试，以及未实现的恢复能力，见 [SORTING_AND_RECOVERY.md](SORTING_AND_RECOVERY.md)。第四轮当时未在 Python 3.12 重跑，后续轮次已补充；断电、硬件故障、所有 OS 错误和真实模型质量未穷举验证。

## 第三轮：程序类型与文件兼容性

最初加入的 11 个兼容性用例在原实现下出现 8 个失败、3 个异常，覆盖已有错误与新增能力缺口；修复并扩展后共 17 项通过。实现范围见 [COMPATIBILITY.md](COMPATIBILITY.md)，回归用例见 `tests/test_compatibility.py`。

| 检查项 | 处理与验证 |
|---|---|
| 无 README 的程序、嵌套多包项目未发现 | 发现 11 类语言生态的清单；标准 JSON/TOML/XML/YAML/INI 按静态字段解析；动态格式保留原文 |
| UTF-16/32 BOM 被当作二进制 | BOM 优先识别，UTF-32 先于 UTF-16；UTF-8/BOM 解码后相同技能仍正确折叠 |
| 旧编码资料无法读取 | 显式 GB18030 / CP1252 / Shift-JIS 回退；来源设置、单文件覆盖、CLI / MCP / HTTP 统一 |
| 编码变更失败后，下一次 stat 未变会误报成功 | 逐条比对实际索引的解码设置；连续失败仍报告不完整，保留旧条目 |
| README 与文档格式过窄 | README 无扩展名与语言后缀；可选 MD/Markdown/MDX/RST/TXT/AsciiDoc |
